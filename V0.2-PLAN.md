**Retires when:** v0.2 ships. At that point this doc moves to `docs/history/V0.2-PLAN.md` or is deleted; durable design content stays in `ROADMAP.md` and `skills/sdd-protocol/SKILL.md`.

## Build order (commit boundary after each phase; no phase starts until the previous phase commits cleanly)

### Phase 0 — M0 design spike (docs + empirical probe; no plugin code)

**Deliverables in `docs/v0.2/`:**

1. **CONTROLS.md** — control inventory table.
   Columns: control name | category (gate / judgment) | current location (hook script / agent prompt / command logic / skill prose) | v0.2 destination (hook / workflow script / subagent frontmatter / retired) | notes.
   Rows: every existing v0.1 control, plus new v0.2 controls the workflows introduce (survival vote, cost ceiling, structured stdout schema validation, etc.).

2. **CONTRACT.md** — workflow ↔ command-layer state-mutation contract. Sections:
   - **State writer pattern**: pick state-writer-subagent vs. return-and-apply. Justify. Default lean: state-writer-subagent (composes naturally with `/deep-research`-shape result emission; keeps command wrapper trivial).
   - **PROGRESS.md ownership**: who writes when, schema if it changes. Likely change: `CYCLE` counter semantics shift from "command-invocation count" to "workflow-run count"; survival rounds inside a single workflow do *not* bump CYCLE.
   - **`.sdd/<feature>/` file ownership matrix**: which files are workflow-mutated, which command-mutated, which append-only.
   - **Structured stdout schema**: JSON envelope. Fields: `feature`, `phase`, `verdict` (clean/revise/escalate), `surviving_concerns` (list), `state_delta` (PROGRESS field updates), `next_legal_commands` (list).
   - **Cost ceiling declaration**: where it lives (proposed: frontmatter at top of `workflows/<name>.js`), how parsed, how surfaced to the caller in headless mode.
   - **Headless-mode contract**: caller responsibilities, dispatch interface, exit-code semantics, how the orchestrator obtains the structured stdout.

3. **Empirical probe — hook-firing matrix.** Run a minimal `/deep-research`-shape workflow in `~/tmp/bf-v0.2-probe/` and record:
   - Does `block-source-before-finalized` fire when a workflow subagent attempts `Edit` outside `.sdd/` with STATUS=DRAFT? *(Expected: yes — tool-call hooks are agent-level, not session-level.)*
   - Does `validate-spec-status` fire on a workflow subagent writing `.sdd/<f>/spec.md`?
   - Does `check-review-written` (SubagentStop) fire per-subagent inside a workflow? With what payload? Does the `subagent_type` field carry the workflow-spawned subagent's identity?
   - Does `stop-tests.sh` (Stop) fire when the workflow finishes, or only when the parent session stops?
   - What is `$CWD` for hook scripts during workflow execution? Same as parent session, or sandboxed?
   - Token cost of the probe workflow at completion.

   Findings recorded in CONTRACT.md § "Empirical hook behavior."

4. **Empirical probe — plugin packaging.** Confirm that `workflows/<name>.js` under the plugin root is discovered as a `/build-fleet:<name>` command after `claude --plugin-dir ./build-fleet`. If not, investigate alternatives (workflows in `.claude/workflows/` at session start? a command that loads and runs a workflow file? Save-as during a session?). This may itself be a v0.2 blocker — escalate immediately if discovery doesn't work.

**Exit criteria for Phase 0:**
- CONTROLS.md complete (every row classified).
- CONTRACT.md complete (every section answered; empirical findings recorded).
- Workflow discovery confirmed in plugin packaging, or alternate distribution path identified.

**Commit:** `docs(v0.2): M0 design spike — controls inventory + workflow contract`

### Phase 1 — M1 review workflow

**New files:**
- `workflows/review.js` — fans out reviewer subagents (architect, qa, coder); runs N cross-examination rounds (default 1, configurable in workflow frontmatter); applies the survival-vote convergence rule; returns the structured stdout envelope from CONTRACT.md.
- `agents/scribe.md` *(if state-writer pattern selected in M0)* — write-only state-applying subagent. Tools: `Read, Write, Edit`. Single responsibility: take a structured delta from the workflow and apply it to PROGRESS.md + REVIEW.md.

**Modifications:**
- `commands/review.md` — no longer does in-line Task fan-out. Now: invoke `workflows/review.js`, parse structured stdout, dispatch to scribe for state mutation, return the converged report.
- `hooks/scripts/check-review-written.sh` — gated behind a "non-workflow REVIEW" guard *or* fully retired per M0's call. The replacement is the workflow's own post-condition (every reviewer must return a structured concerns payload; missing payload halts phase advance).
- `skills/sdd-protocol/SKILL.md` — REVIEW phase rewrite. Convergence rule changes from "all-approved" to "concern survives unless refuted in cross-examination; surviving blockers block FINALIZE; budget exhausted → ESCALATION.md." Cycle budget semantics under workflows clarified.

**Verification:**
- Interactive dry-run: `/build-fleet:review` runs workflow; REVIEW.md ends up with structured cycle entry; PROGRESS.md CYCLE bumps; converged verdict matches survival-vote outcome.
- Headless dry-run: `claude -p '/build-fleet:review'` produces same end-state. End-state diff between modes: empty.
- Planted-blocker test: a reviewer plants `[blocker] for escalation test` with self-disclaiming prose. Survival vote should refute it. Final REVIEW.md is clean. If survival vote does *not* refute, record as a known v0.3 gap; do not block M1.

**Commit:** `feat(v0.2): M1 — review as dynamic workflow`

### Phase 2 — M2 tests-first BUILD ordering

**Modifications only (no new files):**
- `skills/sdd-protocol/SKILL.md` — BUILD phase reordered: on FINALIZE → BUILD transition, qa drafts failing tests against acceptance.md *first*; coder's implementation drives the failing tests to green; CHANGE_REVIEW verifies AC-to-test mapping with tests that fail without the source change.
- `agents/qa.md` — add tests-first directive: in BUILD phase, author tests under `tests/` mapped 1:1 to acceptance criteria, all initially failing, before coder is dispatched.
- `agents/coder.md` — add tests-first awareness: in BUILD phase, do not begin implementation until QA's failing tests exist in `tests/`. Implementation completes when all qa tests pass.
- `commands/finalize.md` — on STATUS=FINALIZED transition, sequence qa-first then coder rather than parallel.

**Verification:**
- New tiny smoke feature (`smoke-test-2`): finalize transitions PHASE=BUILD; qa runs, produces `tests/test_<thing>.py` (or equivalent) all failing; coder runs, implementation makes them green; CHANGE_REVIEW confirms tests would fail without the source.
- Tests-first violation check: temporarily comment out qa's BUILD trigger and confirm coder refuses to begin implementation with no failing tests present.

**Commit:** `feat(v0.2): M2 — tests-first BUILD ordering`

### Phase 3 — M3 build workflow (`/build-fleet:deep-build`)

**New files:**
- `workflows/deep-build.js` — workflow script. Partitions files across N coder subagents (default per-package; configurable via workflow frontmatter); runs them in parallel against M2's failing-test target; runs the adversarial review sub-phase (architect + qa) against the merged diff; returns structured stdout for the command layer to commit.
- `commands/deep-build.md` — slash-command entry point. Dispatches the workflow, applies state delta, returns the merged diff summary.

**Modifications:**
- `commands/finalize.md` — on FINALIZE → BUILD, offers a choice: standard BUILD (M2 ordering) or `/build-fleet:deep-build` based on a `BUILD_MODE` field in PROGRESS.md (which M4's classifier sets).
- `skills/sdd-protocol/SKILL.md` — add `deep-build` phase variant: file-ownership partitioning is part of the workflow plan, exposed in the launch-prompt phase list so the human approves the partition before any coder runs.

**Verification:**
- Contrived 3-package monorepo feature → `/build-fleet:deep-build` fans out 3 coders → review sub-phase consolidates → handoff proceeds.
- Plan-approval surfacing: in interactive mode, the workflow's launch prompt shows the file partition as part of the phase list; rejecting the partition halts before any coder runs.
- Headless mode: structured stdout includes the partition; orchestrator can render to Discord.

**Commit:** `feat(v0.2): M3 — build workflow for fan-out builds`

### Phase 4 — M4 routing front door

**New files:**
- `commands/dispatch.md` — three-tier classifier dispatcher. Reads a feature request, runs the classifier subagent, picks the lane.
- `agents/classifier.md` — subagent that reads a feature description and classifies it as trivial / standard / large.

**Modifications:**
- `commands/new-feature.md` — invokes classifier early. Trivial → skeleton spec is auto-generated by PO; route directly to finalize-and-build (no REVIEW phase). Standard → SPEC phase as today. Large → SPEC phase tagged with `BUILD_MODE=deep-build` so the FINALIZE transition routes to `/build-fleet:deep-build` automatically.

**Verification:**
- Trivial: "fix a typo in README" → fast-path skip, single coder pass, no review.
- Standard: "add a flag to the greet CLI" → standard pipeline.
- Large: "rewrite greet to support multiple languages with i18n loader and locale dispatch" → routed to deep-build at BUILD time.

**Commit:** `feat(v0.2): M4 — three-tier routing dispatcher`

## Cross-cutting concerns to track throughout

- **Workflow file naming convention.** M0 decides. Proposed: `workflows/<command-name>.js` to match the platform's save-as convention (`/<name>`).
- **Plugin packaging for workflows.** Confirmed in M0; if not auto-discovered, the contract changes. Investigate fallback (e.g., command body invokes `Workflow` tool against a workflow file shipped in the plugin tree).
- **`claude -p` verification budget.** Each phase's dry-run runs in both modes — budget ≈ 2× the v0.1 dry-run cost.
- **Plan-approval gate in headless mode.** Verify M0's contract holds: orchestrator surfaces cost ceiling on its own surface (Discord/kanban) before dispatch; workflow runs without launch prompt; no degradation in safety.
